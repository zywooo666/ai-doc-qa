# AI 文档问答助手

基于 RAG（检索增强生成）架构的本地文档问答系统，支持上传 PDF / Word / Markdown / TXT 文档，通过大模型实现基于文档内容的智能问答，有效降低大模型幻觉问题。

## 功能特性

- 📄 **多格式文档支持**：PDF、DOCX、Markdown、TXT
- 🔍 **智能检索**：基于向量相似度检索 Top-3 相关文本片段
- 💬 **多轮对话**：基于文档内容的问答交互
- 📝 **参考来源追溯**：回答附带相关文档片段，可验证依据
- 🎯 **幻觉抑制**：通过 Prompt 工程约束模型基于文档回答，无相关信息时明确告知

## 技术栈

| 层级 | 技术 |
|---|---|
| 后端框架 | Python + Flask |
| RAG 框架 | LangChain |
| 向量数据库 | Chroma（本地持久化） |
| 向量嵌入模型 | 智谱 AI embedding-2 |
| 大语言模型 | 智谱 AI GLM-4-Flash |
| 前端 | HTML + CSS + JavaScript（原生） |

## 快速开始

### 1. 安装依赖

```bash
pip install flask langchain langchain-community langchain-text-splitters chromadb pypdf docx2txt zhipuai
```

在 `app.py` 中配置智谱 AI API 密钥：

```python

```

### 3. 运行

```bash
python app.py
```

浏览器打开 http://127.0.0.1:5000

## 实现原理

### RAG（Retrieval-Augmented Generation）= 检索 + 生成

**文档处理阶段：**
1. 文档加载与解析（PyPDF / Docx2txt）
2. 文本切分（每块 500 字符，重叠 50 字符，保证上下文连贯）
3. 文本向量化（智谱 embedding-2 模型）
4. 存入 Chroma 向量数据库（本地持久化）

**问答阶段：**
1. 用户问题向量化
2. 在向量数据库中检索相似度最高的 Top-3 文本块
3. 将检索到的文本拼入 Prompt 作为上下文
4. 调用 GLM-4-Flash 大模型生成回答
5. 返回回答及参考来源片段

### 为什么用 RAG？

| 对比 | 纯大模型 | RAG 方案 |
|---|---|---|
| 知识来源 | 训练数据（公开信息） | 用户上传的指定文档 |
| 幻觉问题 | 可能编造不存在的信息 | 基于文档内容回答，可追溯 |
| 私有数据 | 无法使用 | 支持企业内部文档、个人资料 |
| 时效性 | 受训练数据截止时间限制 | 上传最新文档即可问答 |

## 关键设计决策

1. **Chroma 向量数据库**：轻量级、本地文件存储、无需额外部署服务，适合个人项目和快速原型
2. **智谱 AI API**：国内可直接访问，新用户有免费额度，embedding + 对话一体化方案
3. **文本切分策略**：500 字符/块 + 50 字符重叠，平衡检索精度与上下文完整性，避免关键信息被切断
4. **Top-3 检索**：召回 3 个最相关片段，在信息量和上下文长度之间取得平衡
